# 硅基流动免费视觉模型试验

本次是模型可行性试验，不是 LoginDeck 自动填写功能的完成验收。

## 试验范围

- 服务：`https://api.siliconflow.cn/v1/chat/completions`。
- 模型：`Qwen/Qwen3.5-4B`，依据试验当天的官方免费模型价格选取，不自动切换模型。
- 用户通过本机临时页面输入 API 密钥；密钥不写入报告、文件或日志。每轮结束后释放应用持有的密钥引用。
- 仅发送生成的虚构窗口图片，不读取真实账号、密码或聊天内容，不操作 QQ，也不提交任何登录。
- 六个场景：中文登录、英文深色登录、扫码、短信验证码、已登录主界面、注册页。

## 判定标准

- 输出必须是可解析且符合约定字段和坐标范围的 JSON。
- 页面类型必须正确；扫码、验证码、已登录及注册页均不得返回填写坐标。
- 对登录页，三个控件的预测中心须位于真实控件内（距边缘至少 4 像素），预测框与真实框的交并比均须不小于 0.5。
- 网络或接口失败单独标为未完成验证，不计作识别正确或定位错误。
- 每个场景只是一张固定图片。全部通过也不能据此推断真实 QQ、多版本、缩放变化或所有应用都支持。

## 第一轮

对应当前目录的 `report.json`、`fixtures.json` 和图片；`login-zh-overlay.png` 的绿色框为实际控件，红色框为模型预测。

- 使用严格 `json_schema` 和图片输入；不指定推理开关，单次请求超时 45 秒。
- 中文登录页：返回可解析且符合字段约定的 JSON，页面类型正确；账号框、密码框和登录按钮的交并比分别为 0.314、0.090、0.000。
- 密码框与登录按钮的预测中心不在目标控件内；不能直接用于执行点击或输入。
- 首张耗时约 37.93 秒。第二张请求超时，后续场景未执行。本轮共发出 2 次请求。

## 第二轮

结果目录为 `run-02/`。进一步明确图片宽高和坐标归一化规则，设置 `enable_thinking=false`，单次等待上限 90 秒。单项网络失败后继续测试其余场景。

已完成全部 6 次请求，无超时，无输出格式降级；全部响应均为可解析的 JSON。但语法正确不代表定位完整或满足业务规则。

| 场景 | 结果 | 说明 | 耗时 |
| --- | --- | --- | --- |
| 中文登录 | 未通过 | 识别为登录页，但三个控件坐标均为 null | 2.38 秒 |
| 英文深色登录 | 未通过 | 缺少密码框坐标，不能执行完整填写 | 3.36 秒 |
| 扫码登录 | 通过 | 正确识别扫码页，三个控件均为空 | 1.32 秒 |
| 短信验证码 | 未通过 | 状态为 verification，但仍返回 username 和 submit 坐标，违反非登录页规则 | 4.18 秒 |
| 已登录主界面 | 未通过严格分类要求 | 返回 unknown 和空坐标，会安全停止，但不能确认已经登录 | 1.92 秒 |
| 注册页面 | 通过 | 返回 unknown 和空坐标，不按登录表单处理 | 2.64 秒 |

完整条件通过 2/6；平均响应约 2.63 秒。两个正向登录样本均失败，因此不能把模型接入直接坐标执行链路。验证码结果应由本地状态与坐标一致性校验拒绝，不能仅凭 JSON 符合结构就继续操作。

## 结论与设计影响

- 在当前试验条件下，免费接口的鉴权、图片输入及严格 JSON 请求已验证可用；该模型的控件定位和规则遵循尚不达标。
- 不将 `Qwen/Qwen3.5-4B` 作为首版自动填写坐标来源，也不将它视为已经适配 QQ。
- 继续以本机控件识别为首选；定位不可靠时手动接管。后续如更换视觉模型，应复用同一套样本和判定条件，再增加真实登录页验证。
- 这是两轮小样本结果，仅评价本次模型与配置，不能推广为硅基流动平台所有模型都不可用，也不能证明更换模型就必然成功。

## 复现

使用安装了 Pillow 的 Python 运行 `scripts/evaluate-siliconflow-vision.py`，指定新的输出目录；只有需要时才传入本机代理参数。程序会输出绑定到 `127.0.0.1` 的临时页面地址，在页面中输入密钥并开始测试。

不要把密钥作为命令行参数、URL 参数或报告内容。页面仅接受本机同源请求；接口重定向被拒绝，避免将鉴权头发送到其他地址。
