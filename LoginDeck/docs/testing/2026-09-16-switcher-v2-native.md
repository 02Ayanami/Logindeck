# 通用切换引擎 v2 与 macOS Driver

> 后续已接入本地配置导入及桌面退出后填写任务，详见 `2026-09-16-adapter-import-execution.md`。以下保留底层实现阶段记录。

## 当前交付

- `autologin_core::switcher`：严格 JSON v2 协议，应用身份、状态选择器、退出／登录流程与预期结果均为数据。支持 click、fill、submit、wait_state、challenge。两个模拟应用只改变配置，复用同一运行器。
- `platform_macos::login::NativeWorkflow`：实现 v2 Driver，复用原生 AX 包装、进程签名核验和执行互斥；支持按钮、菜单项、菜单、静态文本与输入框。
- Driver 由核验后的应用实例和后端账号检查／凭据回调构造。每次读取生成新的句柄令牌；变更前检查进程、前台、窗口、树结构、目标句柄与位置，拒绝过期或已消费的观察。AXPress 派发前消耗令牌，不自动重放超时动作。
- 输入使用定向 AXValue，不经过剪贴板。聚焦后再次检查控件、窗口和空输入，填写期间监视焦点，密码框只验证非空。凭据仅存在于后端 SecretString，不进入配置。
- 退出与提交分别要求引擎调用者提供确认。Challenge 等待用户明确继续；结果 `logged_in_observed` 仅表示命中已登录界面，不能证明是所选账号。

## 验证与边界

v2 与旧 Adapter 定向测试各 7 项通过；平台及桌面编译检查通过。新增 Driver 编译通过，原生登录模块 7 项既有定向测试通过（它们不等价于新 Driver 的实机验证）。本轮没有操作真实应用退出、点击登录或读取真实凭据。

当前 v2 是底层可调用接口，尚未替换桌面 v1 填写任务。用户已确认录制器独立于 LoginDeck：本地命令行 Builder 提供控件选择、步骤编排和 JSON 导出。鼠标录制浮层、外部配置安装、YAML 解析、真实 QQ 退出配置尚未实现。示例 `adapters/examples/switcher-v2.fixture.json` 是模拟数据，不能作为 QQ 适配发布。

首版 Driver 要求目标应用保持前台，且只有一个可确定的窗口。需要回到 LoginDeck 完成 Challenge 的任务协调、系统钥匙串授权后的主动继续，以及多窗口应用支持仍需桌面接入阶段处理；当前 Driver 在前台变化时停止。菜单遍历覆盖窗口子树与 AXMenuBar，不宣称适用于所有自绘或弹出菜单。

独立 Adapter Builder 记录并验证选择器与步骤后输出同一份 v2 配置；核心引擎不包含 QQ 专用退出路径。配置必须经过审阅／确认，控件语义无法仅凭 role 自动证明；不可把任意第三方配置直接视为可信可执行流程。
