# 本地 Adapter Builder

> 历史研发工具：当前 LoginDeck 产品不提供自动登录、账号切换或录制器入口。以下内容仅保留用于研发追溯。

独立命令行录制器，不在 LoginDeck 中提供录制界面，不使用 LoginDeck 数据库或钥匙串。输出普通 v2 JSON 适配文件。

## 运行

在仓库根目录构建一次：

```sh
cargo build -p platform-macos --example adapter_builder --locked
```

之后直接运行本地工具，无需启动 LoginDeck：

```sh
./target/debug/examples/adapter_builder /Applications/QQ.app "$HOME/Desktop/qq-adapter.json"
```

续录已有配置并原位保存：

```sh
./tools/adapter-builder/run.sh /Applications/QQ.app adapters/local/qq-macos-v2-pointer.json --load adapters/local/qq-macos-v2-pointer.json
```

也可以把已有配置加载后写到一个新文件。已有配置必须通过完整校验，并且平台和应用标识符必须与 `.app` 一致。只有 `--load` 的输入与输出为同一文件时才允许替换已有输出；正式保存使用 0600 权限的临时文件和原子替换。同一输出同时只允许一个录制会话，第二个进程会立即报错退出。

`--help` 只显示用法，不打开应用。录制模式会核验并打开参数指定的应用。先在 macOS 系统设置的“隐私与安全性 → 辅助功能”中授权终端／工具；具体被系统列出的宿主以本机提示为准。

## 引导录制退出流程（推荐）

启动带红框预览的版本（需要 Rust 工具链和 macOS Command Line Tools 的 `swiftc`）：

```sh
./tools/adapter-builder/run.sh /Applications/QQ.app "$HOME/Desktop/qq-adapter.json"
```

在主菜单选择“引导录制退出流程（鼠标指认）”：

1. 输入一个新的流程名称，例如 `qq_logout`。工具自动命名各个页面并串起步骤。
2. 按回车，在 5 秒内切回目标应用，把鼠标停在账号菜单按钮上，不要点击。工具通过 AX 原生命中测试列出该控件和可定位祖先；点击步骤只展示按钮或菜单项。
3. 回终端选择候选；再次切回原页面并保持鼠标位置，查看 2 秒红框，再回终端输入 `yes` 确认。红框不抢焦点、不拦截鼠标；显示前会重新识别目标并检查位置。坐标只用于预览，不写入配置。无法得到控件范围时只能确认文字描述。
4. 手动点击刚确认的按钮，告诉向导出现的是下一层菜单／确认页面，还是登录页。遇到弹层时可以把其按钮设为此前页面的排除特征。
5. 如退出点击会重启应用，明确选择“会”；手动操作后等待重启，再按提示重新核验并绑定指定应用。录制期间的重新绑定与执行器的严格重启验证是两个独立环节。
6. 到达登录页后指认一个稳定的登录页特征。向导保留草稿并做交叉校验；发生歧义时使用原有状态编辑和排除弹层功能修正。
7. 使用“重新识别一个已录制页面”，手动重新打开页面后检查规则能否再次识别。
8. 使用“分步试运行退出流程”。它会真实操作当前账号；每一步输入 `run` 后才执行，并等待配置要求的后续状态。可以选择起始步骤；从中途开始通过不代表完整流程通过。点击失败或状态超时立即停止，不自动重试。需要先手动恢复到所选步骤的起始页面。
9. 最后选择“验证并保存文件”。退出流程试运行不会自动保存，也不会读取凭据或提交登录；完整登录由安装配置后的 LoginDeck 在运行前再次确认。

向导中取消或采集失败会撤回本次向导新增的状态和流程，保留此前草稿。红框辅助程序由启动脚本编译到 Rust 示例程序旁；直接运行 Rust 程序且未构建辅助程序时降级为文字确认。没有辅助功能元数据的自绘控件仍不能指认，目前也没有持续跟随鼠标的浮层或全局点击录制。

## 原有手动录制

1. 选择“记录／替换状态”，输入状态名称，选择已登录、登录页、中间菜单或 Challenge 类型。
2. 按回车后有 5 秒准备时间：切到目标应用，手动打开要记录的界面或菜单，并保持目标应用在前台。工具读完后返回终端查看控件列表。
3. 选择控件序号并命名，例如 `menu`、`logout`、`username`、`password`、`submit` 或 `success`。只记录能唯一定位的控件；优先采用标识符，必要时加入祖先条件。
4. 录制所有需要的状态后选择“编排／替换整个流程”。登录流程必须按顺序添加显式清空、凭据填写、必要的同页选项、提交和登录后状态等待；录制器不再提供“仅填写”完成条件。每次点击后选择预期出现的状态。续录时也可选择“替换流程中的单个步骤”，无需重新编排整条路径。
5. 选择“验证并保存文件”，先查看变更摘要和完整配置，输入 `save` 才写入指定路径。新建模式拒绝覆盖已有文件；原位续录只替换通过 `--load` 加载的同一文件。录制中可以删除或替换状态和流程，输入 `q` 退出。

录制不监听全局点击，也不自动操作账号退出。用户手动在应用中完成导航，工具读取页面后提供控件列表供选择。密码输入框通过角色标记，录制器不读取 AXValue、真实密码或验证码。

建议先录制退出：`home` 点击账号菜单 → `account_menu` 点击退出登录 → `login_page` 等待登录页。如果应用需要二次确认，再加入确认状态和点击步骤。然后添加登录页输入、必要选项和提交控件，编排清空、填写、选项点击、提交以及登录后状态等待。协议复选框等选项会进入配置预览，安装和执行前必须由用户检查确认。

## 输出和限制

- 文件只包含被选中的控件描述与流程，不包含完整控件树或未选中的业务文本。控件名称本身可能有个人信息，保存前检查预览。
- 保存前核验状态引用、流程衔接、密码框角色、完成条件，并对本次记录的全部页面做交叉识别；重叠或歧义时拒绝导出。
- 当前只支持 macOS 单个可确定窗口，UI 自绘、无法访问的控件或超出树大小限制会失败。进程重启后需重新启动录制器。
- 只提供 JSON；YAML 和持续鼠标点选浮层未实现；提供定时悬停指认和短暂红框预览。
- 新文件是本地适配草稿，不代表兼容性验收通过。LoginDeck 源码已提供“应用详情 → 本地应用适配 → 导入配置”，安装并识别一个退出流程及一个“填写、提交、观察到已登录”流程后可使用“按配置切换并登录”。保存成功不等同于真实应用兼容性验收通过。
- 每次完成状态、流程、单步替换、删除或排除条件编辑后，工具都会把当前会话写入输出文件旁的 `*.autologin-draft`。草稿可以包含尚未修复的流程引用，但仍受数据模型、64 KiB、数量和标识符限制；恢复草稿不代表配置可执行，正式保存仍执行完整校验。
- 录制器在输出文件旁复用一个权限为 0600 的 `*.autologin-lock` 文件，并在整个会话中持有系统文件锁，防止两个进程互相覆盖草稿或正式配置。进程退出或崩溃后系统自动释放锁；保留的空锁文件不是未完成会话。
- 主菜单可随时查看相对启动时配置的状态／流程新增、删除和修改摘要。正常保存后删除旁路草稿；“退出并保留自动草稿”供下次恢复，“放弃自动草稿并退出”不会修改正式配置。

## 菜单与背景状态重叠

录制器主菜单提供“排除弹出菜单／叠加状态”：选择背景状态、弹层状态和一个弹层特征控件。导出后背景状态的 `absent` 条件要求该控件不存在。例如 QQ 的 `home` 排除菜单项“退出账号”，避免菜单打开时主界面和菜单同时匹配。保存前仍验证全部已录制页面。

## 本地回放诊断

`cargo build -p platform-macos --example adapter_replay --locked` 构建独立诊断工具。传入应用路径与配置路径只观察当前状态，不打印完整控件树。第三个参数为退出流程名称时，会真实执行该退出流程；不支持读取凭据、填写或提交登录。仅在准备好退出当前账号时使用。

已退出后可单独验证配置中的剩余点击，不需要重新登录：

```sh
./target/debug/examples/adapter_replay /Applications/QQ.app adapters/local/qq-macos-v2-recording.json logout --step 2
```

步骤索引从 0 开始。该命令只执行所选退出流程中的一个 Click，要求当前状态与配置一致，并等待配置中的后继状态；不会跳过状态校验，也不会重发点击。单步成功不代表整个退出流程通过。

macOS 原生捕获会请求应用的 `AXManualAccessibility` 元数据支持，在绑定进程及首次观察到新窗口时请求元数据，以恢复 Chromium 类应用在窗口切换后的控件树。不支持此属性的应用继续使用原有树。此操作不读取输入框值，也不触发登录。

同名嵌套按钮可使用选择器 `descendant` 指定后代控件，格式与 `ancestor` 相同。Builder 在名称、标识符和祖先仍无法唯一定位时，尝试记录后代控件关系；不使用序号或坐标猜测。例如外层“更多”按钮可以由其包含的同名按钮区分。

## 退出时应用重启

点击步骤只记录动作及允许出现的 `next_states`。运行器只派发一次点击，然后重新观察目标：同一进程换页面、重建窗口，或由同一路径和签名的新进程接管，都由执行器重新绑定并识别。配置不再猜测应用是否会重启，也不会因为某次运行跳过了中间页面而重复点击。

## QQ 实测注意

QQ 业务界面的“更多”包含同名嵌套按钮。当前候选列表显示由内向外顺序和定位规则；即使选中外层并通过唯一定位，原生点击仍可能不打开菜单。2026-09-17 实测中，该路径单步超时；已有“QQ 菜单栏 → 退出账号 → 账密登录”路径两次完整通过。请优先录制菜单栏入口，并以真实后继页面出现作为点击通过条件。超时提示现在列出步骤、预期页面和最后识别页面，不会自动重复点击。

## 按步骤选择点击方式

录制向导和手动编排现在都可为每个 Click 选择执行方式：

- `accessibility`：辅助功能原生操作。未填写 `method` 的旧配置仍使用此方式。
- `pointer`：先重新定位控件，再以其当前边界中心发送一次真实鼠标按下／释放。配置不保存屏幕坐标，也不读取截图。

例如 QQ 的“更多”步骤：

```json
{
  "type": "click",
  "state": "home",
  "target": "menu",
  "next_states": ["account_menu"],
  "method": "pointer"
}
```

鼠标方式会核验进程、前台、窗口、控件唯一性和位置，并以系统级 AX 命中测试确认中心点属于同一进程的目标或其子控件；命中其他控件／遮挡物时停止。按钮不可用、权限不足、已有鼠标按键或修饰键按住时也停止。输入前消耗本次快照；发送按下后始终发送配套释放。事件发送和窗口变化不能做到系统级原子化，因此点击后仍须观察预期状态。

两种方式不会自动互相补点。试运行失败后，请先检查实际页面、恢复起始状态，再重新编排该步骤的方式。`pointer` 与辅助功能点击使用相同的状态转换与重新绑定逻辑。提交登录仍为独立 Submit 操作。

2026-09-17 新增实测：`adapters/local/qq-macos-v2-pointer.json` 使用鼠标打开业务“更多”并点击“退出账号”，再使用原生操作进入账密登录页。首步单步验证与完整退出均通过，完整回放耗时 4312ms、尝试操作 3 次。上节“QQ 实测注意”描述的是原生方式的历史失败，不适用于这份显式鼠标配置。该配置未安装到现有 LoginDeck；需要本次更新后的执行器，旧版本不认识 `method` 字段。
