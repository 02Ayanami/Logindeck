# Edge 登录捕获首版验证

## 已实现

Edge MV3、逐站 HTTPS 权限、标准登录表单及带明确登录标签的表单内 SPA 按钮、扩展独立确认窗口、保存/更新提示、确认登录成功、拒绝/关闭弹窗/源标签关闭/超时丢弃、按网站不再询问、中英文。

Native Messaging 严格消息与来源校验、短期 SecretString、清零输入缓冲区、元数据匹配、锁内更新冲突检查、Keychain 和 SQLite 协调、桌面与 host 共享跨进程写锁。

## 实际检查

- 扩展 5 项测试通过：保守检测、排除注册/修改/OTP/支付、来源绑定、最小权限、禁止页面伪造确认、仅一次确认写入。
- 桌面前端 84 项测试通过，生产构建通过。
- Rust 工作区 101 项常规测试通过，文档测试通过；2 项默认忽略的专项测试中，子进程锁探针由父测试显式执行。真实钥匙串专项沿用前轮结果，本轮未重新运行。
- 新增 host 测试覆盖保存/更新/过期/重复确认/不读取旧密码/元数据冲突，以及两个独立连接同时提交只允许一个创建。
- Clippy `-D warnings` 通过。
- Edge 解压扩展、native host 可执行文件、更新后的桌面 `.app` 均构建成功。
- 真实 host stdio 消息测试通过：正确 ID 的 status.get 返回中文设置；错误扩展 ID 退出且不输出响应。不保存或读取任何密码。
- 受限沙箱下 native host 无法写入真实应用数据库；获得正常本机权限后状态测试通过，属于测试环境限制。

## 未验收与阻塞

安装用户级 Edge Native Messaging 注册时，自动审批拒绝，理由为尚未明确授权扩展接收方及其对本地密码库的访问范围。未尝试绕过。需要用户确认安装 LoginDeck Edge 扩展和限定该扩展 ID 的本机桥接程序。

当前没有加载到 Edge，没有授权网站，也未捕获真实浏览器登录。不能将自动测试或 host status 测试称为浏览器端到端验收。下一步应使用专用 HTTPS 测试网页和虚构账号验证检测、拒绝、保存、更新、超时、关闭标签与桌面列表同步。

不支持：自动填充、HTTP 网站、跨域 iframe、跨页面两步登录、非标准登录控件、OTP/支付/注册/密码修改。首版不自动判定登录成功，必须由用户勾选确认。

## 安装进度更新

用户明确同意后，已安装用户级 Edge Native Messaging 注册和桥接程序，并核对可执行文件与精确扩展 ID 白名单。之前的审批阻塞已解除。Edge 界面操作时浏览器页面被切换；随后会话不再提供原界面控制工具，因此未加载解压扩展，也未执行真实网页登录验收。剩余步骤是 Edge 的“加载解压缩的扩展”及连接检查。

## 常开模式更新（0.1.1）

按用户要求改为必需 HTTPS host_permissions，安装后默认检测所有 HTTPS 网站，移除逐站开启按钮及 activeTab 权限。仍要求明确登录提交和保存确认，按网站不再询问使用脚本排除规则及后台二次过滤。扩展构建和 5 项测试通过，新增断言覆盖全 HTTPS 注册和排除网站；Edge 实际加载/刷新未在本轮验证。
