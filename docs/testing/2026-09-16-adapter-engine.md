# 配置驱动填写与桌面任务接入

## 已实现

- 严格、带版本的 `AppDefinition` / `LoginState` / `Action` 数据模型和 QQ 内置 JSON。
- 平台无关的角色、名称、标识和祖先选择器；macOS AX 树转换；唯一状态/控件判定。
- 将原 `QqFill` 改为通用 `NativeFill`，由当前识别状态的动作列表驱动账号和密码填写。固定测试探针同样读取 Adapter。
- 后端任务管理与账号页填写入口；绑定已验证的 PID，确认位置后才读钥匙串，系统授权结束后再由用户点击开始填写。
- 取消、任务过期、重复确认拒绝、页面离开取消、账号变更检查和部分输入提示；只展示已填写，不报告已登录。
- 原生输入时监视前台 PID 和焦点窗口，检测到离开后锁定停止状态；仍保留每次定向输入前后的窗口、控件、位置和签名核验。
- 中英文任务弹窗和控件位置示意；示意图不是目标应用截图，无屏幕上传。新账号自动提交默认关闭，当前所有任务均不提交。

## 验证记录

- Rust workspace 测试：120 项通过，2 项原有测试跳过（子进程测试入口和交互钥匙串夹具）。
- Adapter 的 7 项契约测试覆盖模拟第二应用复用、重复控件、同时匹配多状态、错误祖先、非安全密码框、人工交接、拒绝脚本/点击/密码重定向、未知版本、附加标识约束和平台注册表范围。
- 真实 QQ 的配置驱动原生只读探针通过：账号框/密码框均可写、登录按钮禁用。该探针未写入真实凭据。
- 中英文弹窗布局在本地模拟页面检查，英文额外按 800×600 尺寸验证；模拟交互经过位置确认、等待主动开始、已填写三个阶段。模拟页面不调用系统或钥匙串，验证后已删除。

- 前端 94 项测试通过，涵盖基于后端能力显示填写入口、确认后等待主动开始、StrictMode 不启动/取消任务、状态读取失败请求停止，以及 IPC 拒绝密码字段和非法位置。
- Workspace Clippy 严格检查通过；文档测试单独串行通过。一次与打包并行的文档测试曾因共用构建产物报依赖缺失，随后串行重跑通过。
- 最终前端生产构建和 Tauri 调试包构建通过，产物为 `target/debug/bundle/macos/LoginDeck.app`。已停止临时布局测试服务器并删除测试入口。

- 新打包的 LoginDeck.app 辅助功能授权已由用户开启，实机任务成功到达位置确认；示意中的账号框和密码框与 QQ 实际空输入框位置一致。
- 点击位置确认后观察到钥匙串授权等待提示。用户确认随后亲自点击“开始填写”并关闭结果弹窗；独立观察 QQ 账号框和遮蔽的密码框均已有内容，自动登录、记住密码及协议仍未勾选。配置驱动的真实凭据填写链路完成实机验收；弹窗消失是用户关闭，并非已确认的程序故障。未读取密码明文、重复填写或提交登录。

## 尚未验收及限制

- 密码只检查 AX 空/非空状态，不声称验证字符准确或提交逻辑已接受。真实账号登录、验证码和登录成功判断不在本轮验证范围。
- 前台监视为约 10 毫秒轮询，加上每次 AX 操作检查；不能承诺观察到比轮询更短的切换，也不能撤回已发送的系统调用。
- 尚未提供任意配置导入、多步登录、自动退出/提交、Adapter Builder、分享市场或 Session/Credential 插件。
- QQ 规则覆盖本机检查过的中文密码页及带“账密登录”入口的人工准备状态；其它语言、版本和未见界面不宣称兼容。
