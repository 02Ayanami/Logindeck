# 应用登录方式

## 后续调整：取消扫码登录

按用户要求，当前仅提供账号密码和手机验证码。移除扫码选项、扫码任务阶段及人工扫码完成引导；后端拒绝创建或保存扫码类型，也拒绝启动旧扫码记录的登录任务。

保留旧数据库结构和扫码记录读取兼容，不自动删除用户备注。旧记录标注“扫码登录（已取消）”，可删除，或编辑为密码／短信账号；改为密码时必须提供新密码。

前端 106 项测试和生产构建通过；Rust workspace 130 项常规测试通过，2 项既有测试跳过。新增回归覆盖旧扫码记录保存、启动拒绝及删除兼容。文档测试首次因依赖产物缺失失败，单独重跑通过。

以下为取消前的历史实施记录，不代表当前仍支持扫码登录。

## 实现范围

- 账号新增 `login_method`：`password`、`sms`、`qr`。手机号独立保存于 `phone`；扫码的 `username` 仅作可选身份备注。
- 0005 迁移保留旧账号 ID、用户名、凭据引用、时间戳和原有标记，将旧账号归为密码登录。密码引用允许为空，数据库约束拒绝短信/扫码记录携带密码引用。
- 手机验证码只要求手机号（5–15 位数字，可带前导 `+`），不收集或保存验证码；扫码只要求账号名称，可不填身份标识。新请求拒绝未知字段，包括验证码字段。
- 切换表单类型清空未保存的敏感输入；密码账号转为其他类型时，先原子提交元数据和旧凭据清理意图，再删除钥匙串项。失败保留可重试清理任务。切回密码登录需要提供新密码。
- 短信及扫码账号可在没有 CredentialStore 的情况下新增、修改和删除，不生成虚假凭据或占位密码。
- QQ 密码任务继续使用现有适配器、位置确认、钥匙串和二次开始确认流程。短信/扫码账号不能进入密码填写器。
- 新增人工登录引导：核验并打开已保存的应用 → 等待用户完成短信或扫码 → 用户明确确认。终态为 `user_completed`，与密码任务的 `filled` 分开，不写成自动检测到的登录成功。
- 用户仍在目标应用中填写手机号、触发发送和输入验证码，或扫码/手机确认。当前不自动退出、发送短信、识别扫码成功或选择手机端身份；保存某种方式不代表应用已具备该方式的自动化适配。
- 对话框 Escape 仅关闭当前任务，不传播到后面的应用详情面板。
