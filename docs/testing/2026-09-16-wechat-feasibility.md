# 微信适配可行性初查

## 本机观察

- 通过 macOS 辅助功能检查 `com.tencent.xinWeChat`。
- 当前为已登录主窗口；AX 树仅包含窗口、窗口管理按钮及顶层菜单，没有返回主界面的业务控件。
- 视觉核对确认主界面实际存在业务控件，不能将 AX 树缺少控件解释为界面为空。本文不记录聊天内容或截图。
- 没有退出账号、修改设置或操作登录；登录页 AX 可访问性仍未知。

## 结论

当前证据不足以为微信编写可靠的登录 Adapter，不注册支持能力。已登录界面的观察不能外推为所有微信页面均不可访问。

现有 v1 模型要求一个双输入框密码登录状态，人工状态只能提示准备登录页；不能表达完整的扫码等待、手机确认、已登录及退出流程。微信需要先验证登录页，再决定是否扩展状态模型。

## 建议的下一里程碑

先实现只读适配诊断：显示是否存在已验证的 Adapter、当前状态是否匹配、失败原因是权限缺失/未知页面/控件歧义，并给出对应人工操作提示。区分“已有适配能力”与“当前页面可执行”。诊断不读取钥匙串，不填写、不退出，也不保存输入框值。

验收要求：QQ 密码页可识别；无适配的微信明确显示尚不支持，不能误报为权限问题或已支持；未知页面和重复控件安全停止。随后在用户准备好的微信登录页继续只读验证，以实际控件决定扫码流程的支持范围。
