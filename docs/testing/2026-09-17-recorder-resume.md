# 本地录制器续录与草稿恢复

## 实现范围

- `adapter_builder APP OUTPUT --load INPUT` 加载经过完整 v2 校验、且与目标 `.app` 平台和应用标识符一致的配置。
- 输入与输出为同一文件时允许原位保存；其他已有输出仍拒绝覆盖。正式保存使用 0600 临时文件和原子替换。
- 主菜单可以替换整个流程或单个步骤，并显示相对启动配置的状态／流程新增、删除和修改摘要。
- 每次完成编辑以及引导录制的已完成状态／点击步骤后写入 `OUTPUT.autologin-draft`。草稿允许暂时缺少引用目标，但仍受数据模型、64 KiB、数量和标识符限制；正式导出继续执行完整校验。
- 启动时发现草稿会明确选择恢复或删除。成功保存和“放弃草稿”都会删除旁路草稿；正式配置在输入 `save` 前不变。
- 同一输出路径只允许一个录制进程持有会话锁。锁文件权限为 0600，进程退出后系统自动释放；锁文件保留并复用，避免删除锁文件产生并发竞态。

- desktop adapter plan 4 项通过，确认 Builder 变化没有改变桌面执行配置。

## QQ 配置只读实测

使用 `adapters/local/qq-macos-v2-pointer.json` 进行续录启动，不采集控件、不点击 QQ：

- 成功加载并显示 4 个状态、2 个流程。
- “替换流程中的单个步骤”列出 fill 的四个 Clear／Fill 步骤；将第一步替换为等价的 Clear username 后，差异摘要仍为空。
- 无编辑时差异摘要显示状态和流程均无新增、删除或修改。
- “退出并保留自动草稿”生成 3729 字节、权限 0600 的旁路文件。新的录制器进程成功恢复 4 个状态和 2 个流程，“放弃自动草稿并退出”后文件已删除。
- 临时副本以输入输出同路径加载，完整校验后输入 `save`，原位原子保存成功、权限为 0600，且未遗留草稿。仓库中的 QQ 配置没有被该测试覆盖。

## 签名条件

本机 `security find-identity -v -p codesigning` 仍返回 0 个有效身份。稳定签名需要先安装有效的 Apple Development 或 Developer ID Application 证书及私钥；当前只能继续使用会导致辅助功能授权随重签名失效的 ad-hoc 调试包。
